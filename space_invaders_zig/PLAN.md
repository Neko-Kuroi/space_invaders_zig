# Space Invaders Zig 版 計画書

状態: 実装完了 (2026-11-16、未決事項はすべて推奨どおりで承認。報告書は IMPLEMENTATION_REPORT.md)
作成: 2026-11-16
前提の考察: ~/workspace/space_invaders_zig_nim/CONSIDERATION.md

## 1. 目的

C版（リポジトリ最新 958c88f、review2 適用済み）を正本として、
同じ仕様のゲームを Zig で書き直す。これまでの C版・C++版と
並べて、言語ごとの書き方の違いを比べる研究の一環。
ゲームの規則・数値・素材は C版と変えない。

## 2. 置き場所と道具

- 置き場所: `~/workspace/space_invaders_zig/`（C版・C++版とは別フォルダ）
- Zig の版: **0.17.1 に固定**する（この VM に導入済み:
  `~/workspace/zig-tools/zig/`）。Zig はまだ 1.0 前で変化が速く、
  版を上げると書き直しが必要になり得るため、途中で上げない
- ビルドは Zig 標準の `build.zig`（Makefile は作らない）。
  `zig build` で実行ファイル、`zig build test` でテスト

## 3. SDL の取り込み方

- SDL2 本体＋SDL_image＋SDL_mixer＋SDL_ttf の4ライブラリを使う
  （C版・C++版と同じ顔ぶれ、SDL2 のまま）
- バインディングは `zig translate-c` で C ヘッダから自動生成する。
  実測済み: 4つのヘッダから 44,300 行が生成され、SDL_Init まで
  動作した（`~/workspace/zig-spike/`）
- 生成したファイルの扱いは未決事項1（同梱するか、ビルド時に作るか）
- リンク先の SDL は、通常の環境ではシステムの SDL2 開発ライブラリ。
  この VM では C版で使っている展開済みパッケージ
  （`~/workspace/space_invaders_c/.sdl/`）を指す

## 4. 構造（C版と1対1）

| Zig 側 | C版の対応 | 役割 |
|---|---|---|
| `src/logic.zig` | logic.c/h | SDL に触れない純ロジック |
| `src/assets.zig` | assets.c/h | 素材の読み込みと文字描画 |
| `src/game.zig` | game.c/h | ゲームの状態と進行、描画 |
| `src/main.zig` | main.c | SDL 初期化、入力の変換、メインループ |
| `src/sdl.zig` | （生成物） | translate-c のバインディング置き場 |
| `src/root.zig` 等 | — | build.zig からの入り口（必要なら） |

- 定数は C の `#define` を Zig の `const` に写す（名前と値は C版と同一）
- ゲームの状態は Zig の `enum`、データは構造体＋メソッドで持つ
  （Zig には継承がないので、C++版の「控えめなクラス化」と
  自然に同じ形になる）
- Android 用の分岐（タッチ入力・発射ボタン）は、デスクトップ版の
  完成後に別途計画する（第8節）。ただし定数 FIRE_BUTTON_* は
  C版と揃えて最初から置く

## 5. C版との対応で決めておくこと

- **後始末**: C版は手動の free、C++版は RAII。Zig では `defer` で
  解放を書くのが流儀なので、それを使う
- **読み込み失敗**: C版（review2）の方針を維持する。
  音声が使えなければ警告だけで続行し、音の読み込みも省く。
  それ以外の素材の失敗は終了。表現の仕方は未決事項2
- **乱数**: 未決事項3。C版は libc の rand()、C++版は mt19937。
  どの版とも乱数の列の一致は狙わない（仕様は「乱数で選ぶ」こと自体）
- **時刻とペーシング**: C版と同じく PerformanceCounter で
  60fps を積み上げて待つ方式、描画へは同じ `now` を渡す

## 6. テスト

- **logic テスト**: C版の 67 件を Zig に写し、`zig test` で回す
- **スモーク**: 環境変数 `SI_SMOKE_FRAMES=N` の仕組みを C版から
  踏襲し、ダミードライバで 600 / 7,200 フレームを確認する
- **通しテスト（replay）**: C++版で有効だった方式（固定の種＋
  合成入力＋手動時計で状態を固定する）を Zig でも作るかは未決事項4
- ビルドは警告をエラー扱いに寄せ、`zig build` が素通りする状態を保つ

## 7. 素材

images / sounds / fonts は C版フォルダから複写する（C++版と同じ扱い）。

## 8. 範囲外（今回はやらない）

- Android 版（libmain.so 化）。デスクトップ版の完成後に、
  C/C++ の Android プロジェクトへ差し込む形で別途計画する
- SDL3 への移行。今回は SDL2 のまま
- リポジトリへの反映（commit / push は Satoru 側）

## 9. 未決事項（推奨つき）

1. **バインディングの扱い**
   - 案A: 生成した `sdl.zig` をプロジェクトに同梱し、ビルドでは
     それだけを使う（固定されるので検証しやすい）
   - 案B: build.zig の addTranslateC でビルドのたびに生成する
     （ヘッダと常に対一致するが、ビルドが重く、仕掛けも複雑）
   - **推奨: 案A**（C++版で素材を複写して固定したのと同じ考え方。
     SDL の版を上げるときだけ再生成する）
2. **エラーの表現**
   - 案A: Zig の流儀どおり error union（`!` 型）で失敗を返す
   - 案B: C/C++版と揃えて bool と ok() 方式にする
   - **推奨: 案A**（言語の流儀の違いを比べるのが目的なので、
     Zig らしい書き方を採る）
3. **乱数の実装**
   - std.Random の標準実装（DefaultPrng）に固定し、テストでは
     固定の種を使う。**推奨: この案**（C++版で問題になった
     「分布クラスの実装依存」を、Zig では標準の乱数を直接使う
     ことで避けられる）
4. **通しテスト（replay）を作るか**
   - **推奨: 作る**（C++版で、ゲーム本体の自動テストとして
     実際に効いたため）
